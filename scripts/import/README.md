# Car import (JSON → Supabase)

Moves `src/data/car-models.json` into the `diecast` schema. Trucks are intentionally not imported. The mapping rules are in [`docs/SCHEMA.md`](../../docs/SCHEMA.md) §6.

```bash
npm run import:cars                 # dry run (default): real SQL, exact counts, then rolled back
npm run import:cars -- --apply      # write everything in ONE transaction
npm run import:cars -- --plan       # build + validate the payload only, no database call
```

Needs `VITE_SUPABASE_URL` and `SUPABASE_SERVICE_ROLE_KEY` in `.env.local`. The script refuses any key that isn't `service_role`.

## How it works

1. `transform.ts` is pure and unit-tested (`transform.test.ts`). It validates every record and builds the payload. Any **error** stops the run before the database is contacted. **Warnings** are the known data-quality notes (D2, D3, D7, D8, D9, D13, D15), itemized.
2. `run.ts` sends the payload to `diecast.import_collection()` (migration `20260928090000`), which applies it in a **single transaction**:
   - Upserts are keyed by slug and only rewrite rows whose values differ, so re-running reports **0 inserted / 0 updated**.
   - A dry run executes everything, captures the counts, then raises and rolls back.
   - `--fail-after=<step>` injects an error after `brands`, `manufacturers` or `models` to prove nothing partial is left behind.
   - Only the service role can execute the function.

## What it owns (and doesn't)

- **Owns** (overwritten on re-run): the model's name, year, brand, manufacturer, category, scale, `livery_hex`, `is_racing`, `car_number`, driver and `added_at`; its filter colors; and its **position-0** image URLs. Also lookup names and logo paths.
- **Never touches:**
  - description, key features, condition, location, series/team/event, `is_published`;
  - private notes, tags, images at other positions;
  - driver country codes.
- **Never deletes models.** Models in the database but not in the JSON are listed as a warning.

> Once models are edited in the admin UI (Phase 25+), **don't re-run the import**: it would reset the owned columns above to the JSON values. The JSON is archived in Phase 11.

## Inputs (versioned, reviewed)

| File | Purpose |
| --- | --- |
| `driver-aliases.json` | Driver name merges (D5): 143 → 138 |
| `lookups.json` | Brand merges (Corvette → Chevrolet), color names/swatches/order, category slugs, racing categories, manufacturers flagged for review (DTM) |
| `added-dates.json` | `added_at` per model, generated by `npm run import:dates` (`build-added-dates.mjs`) from git history. Renames of ids are followed; models catalogued on the repo's first day (2026-01-11) stay `null` |
